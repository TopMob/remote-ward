## 1. Строгий технологический стек (STRICT STACK POLICY)

1. Проект создаётся **исключительно** на утверждённом системном стеке:
   * **Язык и редакция:** Rust 2021 Edition (компилятор MSVC, целевая платформа `x86_64-pc-windows-msvc`).
   * **Целевая ОС:** Windows 10 / 11 (64-bit).
   * **Графика и захват экрана (Screen Capture):**
     * **Windows Graphics Capture (WGC)** через `windows-capture` / WinRT COM — Zero-Copy D3D11 текстуры напрямую с физического GPU без блокировки локального экрана хоста.
     * **DXGI Desktop Duplication** (`win_desktop_duplication`) в качестве резервного механизма захвата.
   * **Аппаратное кодирование (Video Encode):**
     * **NVIDIA NVENC** (`moq-nvenc` / прямой NVENC C-API) — CBR Ultra-Low Latency, Preset P1/P2 (минимальный инпут-лаг), Zero-Copy импорт D3D11 текстур без промежуточного копирования через CPU RAM.
   * **Аппаратное декодирование (Video Decode):**
     * **Windows Media Foundation (MFT)** Hardware NV12 Decoder — аппаратное декодирование H.264 / HEVC с нулевой буферизацией и субмиллисекундным выводом.
   * **Рендеринг (Video Render):**
     * **Direct3D 11 FastSync Render Pipeline:** SwapChain с эффектом `DXGI_SWAP_EFFECT_FLIP_DISCARD` и флагом `DXGI_SWAP_CHAIN_FLAG_ALLOW_TEARING` (мгновенный вывод кадров в обход задержек композитора Windows DWM).
     * **Contrast Adaptive Sharpening (CAS):** пиксельный HLSL-шейдер адаптивного увеличения резкости для кристальной четкости текста при даунскейле (например, 1440p хоста на 1080p экран ноутбука).
   * **Аудио:**
     * **WASAPI Loopback Capture** (48 кГц, стерео, 32-bit float) на хосте $\to$ **WASAPI Shared Render** с минимальной задержкой буфера на клиенте.
   * **Низкоуровневый ввод (Input System):**
     * Низкоуровневый глобальный хук `WH_KEYBOARD_LL` (перехват Win, Alt+Tab, системных хоткеев).
     * Эмуляция ввода через Win32 `SendInput` (строго аппаратные ScanCode).
     * **Raw Input / Relative Mouse** для плавного обзора камеры на 360° в 3D-редакторах (Blender, Unreal Engine) и играх.
   * **Сетевой транспорт (UDP Ultra-Low Latency):**
     * Кастомный UDP сокет (`socket2`) с non-blocking I/O и оптимизацией буферов (`SO_RCVBUF`, `SO_SNDBUF` по 4–8 МБ).
     * **Reed-Solomon Erasure Coding** (`reed-solomon-erasure` с SIMD) для упреждающего восстановления потерянных UDP-пакетов без ожидания сервера.
     * **Селективный NACK Retransmit** (быстрый дозапрос утерянных фрагментов с отсечкой по RTT).
     * **Микросекундный пейсер (PacedSender):** высокоточный мультимедийный таймер Windows (`timeSetEvent`) для сглаживания микро-всплесков трафика (micro-bursts) и предотвращения bufferbloat.
     * **Wi-Fi QoS:** маркировка пакетов DSCP 46 (Expedited Forwarding / приоритет очередей WMM Video/Voice).
     * **NAT Traversal & Discovery:** клиент STUN (RFC 5389, Google/Cloudflare) и UDP LAN Discovery (239.255.0.1 / Broadcast).
   * **Асинхронность и многопоточность:**
     * Tokio 1.43 (`full`), Rayon 1.10 (параллельные вычисления), `parking_lot` (быстрые мьютексы/rwlock'и), `crossbeam-channel` (высокопроизводительные lockless очереди).
   * **Клиентский GUI:**
     * `winit` v0.30 + `egui` v0.30 (`egui-winit`) — ультралегковесный, отзывчивый GUI-интерфейс лаунчера и настроек без раздувания бинарника.
   * **Сериализация и структуры:**
     * `bytemuck` (Zero-Copy POD casting для заголовков пакетов), `bincode` (компактная сериализация команд), `serde` / `serde_json`.
   * **Диагностика и ошибки:**
     * `tracing`, `tracing-subscriber`, `thiserror`, `anyhow`.
2. **Категорически запрещено:**
   * Тащить тяжелые сторонние фреймворки (Electron, Tauri, Qt, WebView, C++ SDL и т.д.).
   * Менять стек кодеков или конвейер рендеринга (например, заменять D3D11 / NVENC / MFT на тяжелый FFmpeg CLI / GStreamer, ломая Zero-Copy архитектуру).
   * Блокировать асинхронный рантайм Tokio вызовами `std::thread::sleep` или тяжелыми синхронными COM/D3D11 вызовами (выносить их в выделенные системные потоки или `spawn_blocking`).
   * **Любое добавление внешних библиотек (crates) требует явного предварительного согласования с пользователем.**

## 3. Качество против ИИ-слопа в системном программировании (ANTI-AI-SLOP & CRAFTSMANSHIP)

1. **Никакого кода-заглушки (Zero Placeholders):**
   * Категорически запрещены `todo!()`, `unimplemented!()`, пустые функции-заглушки вида `Ok(())`, фейковые моки в продакшен-коде или закомментированные куски логики.
   * Если модуль или функция создаётся — она обязана быть полностью рабочей, типизированной и обработанной на все возможные системные ошибки.
2. **Культура Zero-Allocation на горячем пути (Hot Path):**
   * Кадр видео формируется и передается 60–120 раз в секунду. В цикле захвата кадра (`WGC` $\to$ `NVENC` $\to$ `Packetize` $\to$ `UDP Send`) и конвейере клиента (`UDP Recv` $\to$ `Reassemble` $\to$ `MFT Decode` $\to$ `D3D11 Render`):
     * **Категорически запрещены динамические аллокации памяти в цикле кадра:** никаких `Vec::new()`, `vec![]`, `format!()`, `to_string()`, клонирования тяжелых буферов.
     * Использовать предварительно выделенные пулы буферов (Buffer Pool), переиспользование структур с `.clear()`, слайсы `&[u8]`, кольцевые очереди и zero-copy кастинг через `bytemuck`.
3. **Строгие стандарты работы с `unsafe` и Windows FFI:**
   * Любой блок `unsafe` обязан быть минимальным по объему и сопровождаться исчерпывающим комментарием: `// SAFETY: <четкое системное обоснование валидности указателя, времени жизни буфера или соблюдения инвариантов Win32 API>`.
   * Все HRESULT и COM-методы Windows SDK обязаны валидироваться (`.ok()?` или явная проверка `FAILED(hr)`). Запрещено игнорировать ошибки инициализации DirectX / Media Foundation / WASAPI.
   * Корректная модель COM-апартаментов: системные потоки, работающие с COM/WinRT, обязаны корректно инициализировать апартаменты (`CoInitializeEx` с `COINIT_MULTITHREADED`).
4. **Отказоустойчивость конвейера (Pipeline Resilience):**
   * Переключение мониторов (<kbd>F8</kbd>) и изменение разрешения хоста не должны приводить к падению: MFT декодер и D3D11 SwapChain должны корректно переинициализироваться на лету (Zero-Crash recovery).
   * Все глобальные системные ресурсы (хук клавиатуры `WH_KEYBOARD_LL`, D3D11 ресурсы, сокеты, дескрипторы мультимедийного таймера) обязаны гарантированно освобождаться в `Drop` (`UnhookWindowsHookEx`, `timeKillEvent`).

## 4. Системная безопасность, устойчивость и защита от сбоев (SYSTEM STABILITY & LOW-LEVEL SECURITY)

Приложение взаимодействует с сетевым UDP-стеком, низкоуровневыми хуками ОС, видеокартами и драйверами Windows. Надежность и безопасность исполнения — приоритет №1:

### 4.1. Защита от повреждения памяти и Fuzz-proof разбор пакетов
* Все входящие UDP-датаграммы (видео, аудио, управление, ввод) являются потенциально враждебными:
  * Обязательная проверка заголовков: `magic` (`0x5257`), версия протокола, соответствие размера буфера и поля `payload_len`.
  * Запрещен unchecked slicing или приведение типов «наугад»: кастинг в POD-структуры через `bytemuck` производить только после строгой проверки `buf.len() >= size_of::<T>()`.
  * Категорически запрещены `unwrap()` и `expect()` на входящих сетевых данных — возвращать строго типизированные ошибки (`Result<_, ProtocolError>`).

### 4.2. Защита от DoS и переполнения очередей (NACK & Packet Storms)
* **Защита от NACK-шторма:** лимитирование частоты и объема повторных запросов пакетов, чтобы кратковременный джиттер или потеря пакетов по Wi-Fi не вызывали взрывную лавину ретрансмитов и насыщение канала.
* **Защита рессемблера:** жесткое ограничение максимального количества удерживаемых в памяти кадров (Drop stale frames) для предотвращения утечек оперативной памяти (OOM) при потере ключевого кадра.

### 4.3. Безопасность инъекции ввода (Input Sanitization & Host Integrity)
* Хост принимает события мыши и клавиатуры из сети:
  * Координаты курсора обязаны нормализоваться и жестко проверяться на границы активного экрана хоста (отсечение отрицательных или некорректных значений).
  * Санитизация ScanCode: фильтрация недопустимых виртуальных кодов, предотвращение атак через поддельные системные последовательности.
  * **Защита от залипания клавиш (Stuck Keys):** при обрыве связи или таймауте сессии хост обязан автоматически сбрасывать состояние всех зажатых кнопок мыши и клавиш клавиатуры.

### 4.4. Потокобезопасность, приоритеты и предотвращение Deadlock'ов
* **Изоляция потоков:**
  * Поток цикла сообщений Windows (`winit` EventLoop) никогда не должен блокироваться сетевыми операциями или кодированием видео.
  * Поток таймера пейсера (`PacedSender`) работает с наивысшим приоритетом реального времени (`THREAD_PRIORITY_TIME_CRITICAL`), но содержит строго минимальную логику без долгих блокировок.
  * Категорически запрещено удерживать синхронные мьютексы `parking_lot::Mutex` через точки ожидания `.await` в асинхронном рантайме Tokio.

### 4.5. Защита ресурсов GPU и дескрипторов ОС
* Предотвращение утечек видеопамяти (VRAM leaks) и дескрипторов Windows (`HANDLE`, `HHOOK`, `SOCKET`):
  * Строгий контроль времени жизни COM-объектов DirectX (`ID3D11Texture2D`, `ID3D11DeviceContext`).
  * При завершении приложения хук клавиатуры обязан безоговорочно сниматься (`UnhookWindowsHookEx`), исключая блокировку клавиатуры в ОС.

### 4.6. Гигиена логирования (High-Frequency Log Flood)
* При частоте 60–120 FPS категорически запрещено писать логи уровня `info!` или `warn!` на каждый кадр или сетевой пакет.
* Для горячего пути использовать уровень `trace!` либо периодическую сводку (раз в 1–2 секунды выводить агрегированную телеметрию: FPS, RTT, битрейт, потери пакетов).
